# 路书 Agent 一期范围裁剪记录

> 日期：2026-08-07
> 原则：先完成最小闭环；没有稳定事实数据接口的能力不进入首版。

## 1. 一期产品定义

用户通过对话提供路线需求，系统把需求转换为一份可保存、可修改、可在地图上展示的结构化路书。

首版的“可执行”定义为：地点可以定位、路线可以连接、每日安排连续、距离和预计耗时可计算，并能展示带时效状态的天气预报。它不代表系统已经核实营业、预约、票价、库存和临时管制，天气预报也不构成确定事实或安全保证。

## 2. 外部数据依赖

首版接入两个相互独立的数据源。

### 2.1 高德开放平台

提供：

- 地点关键字检索；
- 地理/逆地理编码；
- 地点坐标和基础类别；
- 驾车与步行路径；
- 路线距离和预计耗时；
- 前端地图展示。

优先选择高德开放平台。MVP 不实现百度、高德、OSM 多供应商聚合，不处理跨供应商地点合并。

### 2.2 和风天气 API

提供：

- 行程日期范围内的逐日天气预报；
- 临近行程的逐小时天气预报；
- 可获取时的官方灾害预警；
- 温度、天气现象、降水、风力等基础字段。

天气数据必须记录查询时间、供应商更新时间、预报适用时间和过期状态。天气接口失败时保留上一份尚可展示的数据并标记过期；没有可用数据时显示“天气暂未获取”，但不得阻断路线生成。

## 3. 功能清单

### P0：必须实现

1. 创建并保存路书草稿；
2. 对话提取基础需求和少量关键补问；
3. 地点搜索、候选消歧和用户确认；
4. 生成按天组织的地点列表；
5. 生成地点之间的路线、距离和预计耗时；
6. 按每日主要地点查询逐日天气，临近出行时可查询逐小时天气；
7. 在行程日展示天气、灾害预警、查询时间和有效状态；
8. 对明显恶劣天气给出提示，但由用户决定是否调整行程；
9. 地图、标记、路线和每日行程联动；
10. 增加、删除、替换地点和修改某一天；
11. 高影响修改确认后再写入；
12. 保存版本并撤销最近一次修改；
13. 检查日期连续、地点有坐标、路线可连接、必去/排除约束；
14. 生成一个固定布局的最终 HTML 路书页面。

### 明确不做

- 景点开放时间、门票和预约；
- 火车、航班、公交实时班次及余票；
- 酒店搜索、实时房价和预订；
- 餐厅推荐及营业状态；
- 充电桩、加油站实时可用性；
- 精确费用预算；
- 实时路况、临时管制和导航；
- 自动下单、支付、多人协作和多格式导出；
- 多地图供应商容灾和境外路线。

### 用户可手工补充

以下内容只作为文本备注或用户确认事实保存，不由系统自动验证：

- 酒店名称和入住信息；
- 已购车次、航班和出发时间；
- 景点门票、预约码和开放时间；
- 餐厅、预算、装备和注意事项。

## 4. 最小结构化路书

```json
{
  "id": "routebook_id",
  "title": "路线名称",
  "status": "draft|pending_confirmation|final",
  "requirements": {
    "origin": {},
    "start_date": "2026-10-01",
    "days": 3,
    "transport_mode": "driving",
    "must_visit": [],
    "excluded": []
  },
  "days": [
    {
      "date": "2026-10-01",
      "items": [],
      "segments": []
    }
  ],
  "weather": [
    {
      "date": "2026-10-01",
      "location": {},
      "forecast": {},
      "alerts": [],
      "status": "verified|stale|unavailable",
      "fetched_at": "2026-09-30T08:00:00+08:00"
    }
  ],
  "notes": [],
  "warnings": [],
  "version": 1
}
```

地点只需要内部 ID、供应商 ID、名称、地址、坐标、坐标系和用户确认状态。路线段只需要起终点、方式、距离、预计耗时和供应商查询时间。

## 5. 固定免责声明

所有草稿和最终页面展示：

> 本路书依据地点、地图路线及和风天气预报生成。天气预报可能变化；景点开放、预约、票价、交通班次、住宿库存及临时管制未自动核实，请在出发前通过官方渠道确认。

## 6. MVP 验收场景

使用一个 3 天的中国境内路线完成验收：

1. 用户用一句话提供出发地、日期、交通方式和 3～5 个地点；
2. 系统对重名地点进行一次消歧；
3. 生成三天行程并在地图显示；
4. 展示每日距离、预计交通耗时和对应日期天气；
5. 模拟天气接口失败，确认路线仍能生成并显示明确降级状态；
6. 用户要求替换第二天一个地点；
7. 系统预览影响，确认后只更新第二天及关联路线和天气位置；
8. 产生新版本并可撤销；
9. 检查通过后生成最终 HTML 页面。

只要上述闭环稳定完成，即视为 MVP 达标。被裁剪的数据能力不作为阻断项。
