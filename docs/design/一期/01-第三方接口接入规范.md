# 一期第三方接口接入规范

> 文档版本：V1.0
> 更新日期：2026-08-07
> 适用范围：路书 Agent 一期服务端
> 关联需求：`requirements/01-路书Agent一期功能需求.md`

## 1. 目的

本文规定一期高德地图和和风天气 API 的调用边界、内部字段映射、缓存、错误处理和凭证安全要求。

第三方原始响应不得直接成为路书业务对象。所有响应必须经过服务端适配器规范化，再写入当前路书版本。

## 2. 配置

服务端使用以下环境变量：

```dotenv
AMAP_API_KEY=<server-side-secret>
QWEATHER_API_KEY=<server-side-secret>
QWEATHER_API_HOST=<project-api-host>
```

规则：

- 真实值只配置在部署环境或本地 `.env`；
- 仓库仅允许提交 `.env.example`；
- 前端不得获得 Web 服务 API Key；
- 日志不得记录认证 Header 或包含 Key 的完整 URL；
- API Key 不得写入路书配置、版本快照和分享页面。

## 3. 高德地图接口

### 3.1 通用约定

- Base URL：`https://restapi.amap.com`；
- 坐标顺序：`longitude,latitude`；
- 坐标系：GCJ-02；
- 成功条件：HTTP 2xx、`status = "1"` 且 `infocode = "10000"`；
- 鉴权参数由服务端适配器注入，业务层不得传递 Key；
- 所有请求设置连接超时、响应超时和有限重试。

### 3.2 地理编码

用途：将用户输入的地址或明确地点转换为坐标。

```http
GET /v3/geocode/geo
```

请求参数：

| 参数 | 必填 | 来源 |
| --- | --- | --- |
| `address` | 是 | 用户地点文本 |
| `city` | 否 | 已确认城市或行政区 |
| `key` | 是 | 服务端配置 |

内部返回：

```json
{
  "formatted_address": "湖北省武汉市武昌区黄鹤楼",
  "longitude": 114.302467,
  "latitude": 30.544649,
  "coordinate_system": "GCJ-02",
  "match_level": "兴趣点",
  "status": "verified"
}
```

无结果时返回 `PLACE_NOT_FOUND`，不得由模型生成坐标。

### 3.3 POI 关键字检索

用途：查找地点候选、取得高德 POI ID 和基础属性。

```http
GET /v5/place/text
```

请求参数：

| 参数 | 必填 | 来源 |
| --- | --- | --- |
| `keywords` | 是 | 用户输入的地点名称 |
| `region` | 建议 | 已确认城市或行政区 |
| `show_fields` | 否 | 一期按需要请求基础业务字段 |
| `key` | 是 | 服务端配置 |

内部候选结构：

```json
{
  "provider": "amap",
  "provider_place_id": "B001B0I4K0",
  "name": "黄鹤楼",
  "address": "蛇山西山坡特1号",
  "district": "武昌区",
  "longitude": 114.302467,
  "latitude": 30.544649,
  "coordinate_system": "GCJ-02",
  "category": "风景名胜",
  "status": "verified"
}
```

候选处理：

- 唯一且城市、行政区匹配时可以自动采用；
- 多个合理候选时返回前端供用户确认；
- 不允许仅按第一条结果静默确定重名地点；
- 内部地点以自有 `place_id` 为主键，高德 ID 作为外部标识。

### 3.4 驾车路径规划

用途：生成驾车路线段及距离、预计耗时。

```http
GET /v5/direction/driving
```

关键参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `origin` | 是 | 起点 GCJ-02 坐标 |
| `destination` | 是 | 终点 GCJ-02 坐标 |
| `show_fields` | 否 | 一期需要 `cost` 等字段 |
| `key` | 是 | 服务端配置 |

一期默认采用供应商返回的首选路线，不实现多路线比较。内部结构：

```json
{
  "provider": "amap",
  "mode": "driving",
  "origin_place_id": "place_1",
  "destination_place_id": "place_2",
  "distance_meters": 9484,
  "duration_seconds": 1224,
  "tolls_yuan": 0,
  "traffic_lights": 15,
  "status": "verified",
  "fetched_at": "2026-08-07T15:00:00+08:00"
}
```

### 3.5 步行路径规划

用途：生成步行路线段。一期使用高德当前正式步行路径接口，参数与返回字段由适配器转换为与驾车相同的内部 `RouteSegment`，其中费用和红绿灯字段允许为空。

### 3.6 高德错误映射

| 情况 | 内部错误 | 是否重试 | 一期行为 |
| --- | --- | --- | --- |
| 无地点结果 | `PLACE_NOT_FOUND` | 否 | 请求用户补充城市或地址 |
| 多候选 | `PLACE_AMBIGUOUS` | 否 | 请求用户选择 |
| 无可用路线 | `ROUTE_NOT_FOUND` | 否 | 保留地点，路线标记未验证 |
| 超时/网络失败 | `PROVIDER_UNAVAILABLE` | 是，有限次数 | 使用缓存或明确降级 |
| 限流 | `PROVIDER_RATE_LIMITED` | 延迟重试 | 使用缓存，禁止密集重试 |
| 鉴权失败 | `PROVIDER_AUTH_FAILED` | 否 | 记录脱敏错误并告警 |
| 其他业务错误 | `PROVIDER_ERROR` | 视情况 | 不覆盖已有有效结果 |

## 4. 和风天气接口

### 4.1 通用约定

- Base URL：`https://{QWEATHER_API_HOST}`；
- 认证方式：`X-QW-Api-Key` 请求头；
- 不使用 URL Query Key；
- HTTP 客户端必须启用 gzip/Brotli 等响应自动解压；
- 成功条件：HTTP 2xx 且响应 `code = "200"`；
- 地点参数使用经纬度，顺序为 `longitude,latitude`；
- 天气数据必须保存供应商更新时间和本地查询时间。

### 4.2 三日天气预报

```http
GET /v7/weather/3d?location={longitude},{latitude}
X-QW-Api-Key: <server-side-secret>
```

用途：为处于预报范围内的每日主要停留地点查询基础天气。

一期规范化字段：

```json
{
  "provider": "qweather",
  "location_place_id": "place_1",
  "forecast_date": "2026-08-07",
  "temp_min_c": 27,
  "temp_max_c": 36,
  "text_day": "晴",
  "text_night": "晴",
  "wind_scale_day": "1-3",
  "provider_updated_at": "2026-08-07T14:33:00+08:00",
  "fetched_at": "2026-08-07T14:45:00+08:00",
  "status": "verified"
}
```

### 4.3 24 小时逐小时预报

```http
GET /v7/weather/24h?location={longitude},{latitude}
X-QW-Api-Key: <server-side-secret>
```

只在行程临近且页面需要小时级信息时查询。核心字段：

- `fxTime` → `forecast_at`；
- `temp` → `temperature_c`；
- `text` → `weather_text`；
- `windScale` → `wind_scale`；
- `precip` → `precipitation_mm`。

### 4.4 灾害预警

```http
GET /v7/warning/now?location={longitude},{latitude}
X-QW-Api-Key: <server-side-secret>
```

核心字段：预警 ID、发布机构、标题、严重程度、开始时间和结束时间。

`warning: []` 是成功且无预警，不得映射为错误。预警只生成页面提示和调整建议，不自动修改路书。

### 4.5 天气状态与错误映射

| 情况 | 状态/错误 | 一期行为 |
| --- | --- | --- |
| 查询成功 | `verified` | 展示天气和查询时间 |
| 超出预报范围 | `unavailable` | 展示“尚未进入可预报范围” |
| 缓存超过有效期 | `stale` | 可展示旧值，但必须标记过期 |
| 无预警 | `verified` + 空数组 | 正常展示，不提示错误 |
| 超时或网络失败 | `PROVIDER_UNAVAILABLE` | 不阻断路线生成 |
| 限流 | `PROVIDER_RATE_LIMITED` | 使用缓存或显示暂不可用 |
| 鉴权失败 | `PROVIDER_AUTH_FAILED` | 脱敏告警，不重试 |
| 响应不可解析 | `PROVIDER_BAD_RESPONSE` | 保存诊断元数据，不保存原始敏感内容 |

## 5. 缓存与刷新

| 数据 | 一期缓存建议 | 刷新触发 |
| --- | --- | --- |
| POI 基础信息 | 较长缓存 | 用户重新搜索或地点失效 |
| 地理编码 | 较长缓存 | 输入地址发生变化 |
| 路线 | 按起终点、方式和请求参数缓存 | 路线地点或方式变化 |
| 三日天气 | 按地点、日期和供应商更新时间缓存 | 用户刷新或缓存过期 |
| 24 小时天气 | 短缓存 | 临近出行且缓存过期 |
| 灾害预警 | 短缓存 | 页面刷新或有效期变化 |

具体 TTL 在技术实现阶段配置化，不写死在业务代码中。

## 6. 调用编排

生成一期路书时：

1. 先完成地点搜索和用户消歧；
2. 所有正式地点取得 GCJ-02 坐标；
3. 按每日地点顺序查询相邻路线段；
4. 按每日主要停留地点查询天气；
5. 可并行的路线段、每日天气和预警请求并行执行；
6. 规范化结果写入同一个待生成路书版本；
7. 地图数据满足要求即可生成初稿，天气失败仅增加降级提示。

局部修改时，只重新查询受影响的地点、路线段和天气位置。

## 7. 日志与监控

每次供应商调用记录：

- provider、operation、request_id；
- 开始时间、耗时、HTTP 状态和脱敏后的业务状态；
- 是否命中缓存、是否重试、最终内部错误类型；
- 不记录 Key、认证 Header、用户敏感地址和完整原始响应。

至少监控调用成功率、P95 延迟、限流次数、鉴权失败、无结果率和降级次数。

## 8. 已验证接口

地理编码、POI 搜索、驾车路径、三日天气、24 小时天气和灾害预警已于 2026-08-07 使用实际凭证验证成功。具体结果见 `research/03-第三方接口验证记录.md`。

步行路径应在开发适配器时补充一次真实接口验证，并将结果追加到验证记录。
