> 状态：自动化门禁已建立；真实依赖故障演练、生产压测和小范围试用需在目标环境留证后签署发布。

## 已实现门禁

- `scripts/release_gate.py` 串联凭证扫描、Ruff、Mypy、合同漂移、Prompt 回放、后端、前端、生产构建和 compose 校验；
- `tests/test_phase8_release_safety.py` 覆盖生产配置拒绝和嵌套日志脱敏；
- 生产配置拒绝 HTTP CORS、示例数据库凭证和 DEBUG 日志；
- 同一版本与隐私策略只允许一个有效分享页，分享页支持幂等撤销，撤销 token 不再可读；
- `scripts/phase8_fault_drill.sh` 提供显式启用的 Redis、PostgreSQL 和 Worker 重启演练；
- `docs/operations/phase8-runbook.md` 固化部署、回滚、备份恢复、人工重试、监控和告警要求。
- 修复新建路书空版本任务与首条需求任务并发提交导致的版本冲突，并加入真实数据库回归测试。
- 修复 compose 未向 API/Worker 传递高德、和风凭证和供应商超时策略导致推荐接口必然失败的问题。
- 浏览器 API 与 SSE 改走 Next.js 同源代理，避免跨端口并发刷新造成间歇性 `Failed to fetch`。
- 工作台刷新后恢复服务端推荐批次；最终页生成改为可靠同页跳转，避免异步弹窗被浏览器拦截。

## 本地真实完整流程记录（2026-08-14）

使用 Docker Compose、真实模型、高德 POI/路线、和风天气和浏览器完成：一句话需求 →
需求版本 v2 → 必去地点优先召回 → 接受三个真实 POI → 三日行程/地图版本 v3 → 固定版本分享页。
本轮发现并修复首条需求版本竞态、供应商凭证未注入、必去文本未落为 POI、跨端口请求不稳定、
推荐刷新丢失和最终页弹窗拦截六个集成缺陷。

1. 带 PostgreSQL/Redis 的集成测试和本手册故障演练；
2. 真实高德/和风受保护烟测，以及超时/配额耗尽时的降级记录；
3. 目标规格下核心 API、Graph 和 1～7 天行程场景的 P95 压测；
4. 依赖漏洞扫描结果及 P0/P1 缺陷清单；
5. 脱敏真实场景小范围试用的更正、拒绝、失败和修复不收敛样本；
6. 备份恢复抽查、应用镜像回滚和告警送达记录。

上述证据全部满足后，方可将本审计状态改为“通过”并冻结 `0.1.0` 发布候选。
