# 路书 Agent 一期功能需求

> 文档版本：V1.0
> 文档状态：一期开发基线
> 更新日期：2026-08-07
> 适用阶段：原型设计、技术设计、开发与验收

## 1. 产品定义

路书 Agent 一期（MVP）是一个通过自然语言生成和修改旅行路线的最小应用。

用户描述出发地、日期、交通方式和想去的地点后，系统识别需求、补问必要信息，通过高德地图获取地点与路线，通过和风天气获取基础天气，最终形成一份按天组织、可在地图展示、可局部修改和保存版本的结构化路书。

一期的核心目标是验证以下闭环：

> 对话输入 → 结构化需求 → 地点确认 → 路线生成 → 天气展示 → 地图路书 → 局部修改 → 版本保存 → 最终页面

## 2. 产品目标

### 2.1 用户目标

- 用户可以从一句自然语言开始规划路线；
- 用户不需要手工查询地点坐标和地点间距离；
- 用户可以看到按天组织的路线、地图和基础天气；
- 用户可以只修改某一天或某个地点；
- 用户可以确认重要修改，并撤销最近一次修改；
- 用户可以生成一份固定布局的最终路书页面。

### 2.2 一期成功标准

- 能稳定完成一个中国境内 1～7 天路线规划；
- 能处理 3～15 个主要地点；
- 地点、路线、行程列表和天气使用同一版路书数据；
- 修改某一天时，不无故改写其他日期；
- 外部接口失败时，已生成的有效路书不会丢失；
- 完成需求中的端到端验收场景。

## 3. 一期功能范围

### 3.1 支持范围

- 地区：中国大陆；
- 行程长度：1～7 天；
- 地点数量：建议 3～15 个主要地点；
- 路线方式：驾车、步行；
- 输入方式：自然语言对话；
- 输出方式：应用内地图路书和固定布局 HTML 页面；
- 外部数据：高德地图、和风天气。

### 3.2 不支持范围

- 公交、铁路和航班班次、票价、余票及实时状态；
- 酒店搜索、房态、价格和预订；
- 景点营业时间、门票、预约和实时客流；
- 餐厅推荐及营业状态；
- 充电桩、加油站实时可用性；
- 精确预算和实时价格；
- 实时导航、实时拥堵预测和临时道路管制；
- 自动预订、下单和支付；
- 境外路线和多地图供应商；
- 多人协作、复杂权限和多格式导出；
- 专业户外及高风险路线安全决策。

上述信息允许用户以备注形式手工补充，但系统不自动验证。

## 4. 用户输入与系统输出

### 4.1 最小输入

生成初稿前必须明确：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 出发地 | 是 | 城市或可定位地点 |
| 开始日期 | 是 | 用于生成每日行程和查询天气 |
| 天数 | 是 | 1～7 天 |
| 交通方式 | 是 | 驾车或步行 |
| 目标地点 | 是 | 至少一个目的地或想去地点 |
| 必去地点 | 否 | 不能被系统自动删除 |
| 排除地点 | 否 | 不得加入正式方案 |
| 每日强度偏好 | 否 | 轻松、适中、紧凑，默认适中 |
| 用户备注 | 否 | 酒店、已购票、预约等人工事实 |

当开始日期超出天气接口的有效预报范围时，仍可生成路线，但不展示远期天气预测。

### 4.2 核心输出

- 路书标题、日期、天数和交通方式；
- 已确认需求和仍缺少的信息；
- 按天组织的地点和活动列表；
- 地点间路线、距离和预计耗时；
- 每日主要停留地的天气及预警；
- 地图标记和分日路线；
- 未验证信息、接口失败和风险提示；
- 当前版本号和最近一次修改摘要；
- 固定布局最终 HTML 路书页面。

## 5. 核心用户流程

### 5.1 创建路书

1. 用户输入初始旅行需求；
2. 系统提取结构化字段；
3. 系统展示已理解内容和关键缺失项；
4. 每轮最多询问 1～3 个阻断问题；
5. 最小输入齐全后进入地点确认。

### 5.2 地点确认与生成初稿

1. 系统通过高德搜索地点；
2. 唯一匹配时直接采用，并标记为系统匹配；
3. 存在重名或多个合理候选时，展示候选名称、地址和行政区；
4. 用户确认地点后，系统安排每日顺序；
5. 系统查询相邻地点路线；
6. 系统查询每日主要停留地天气；
7. 系统生成结构化路书和地图页面；
8. 初稿保存为版本 1。

### 5.3 局部修改

1. 用户通过对话提出增加、删除、替换地点或修改某一天；
2. 系统识别最小影响范围；
3. 删除必去地点、修改多日或改变主要路线时生成待确认提案；
4. 页面预览修改结果，但不覆盖当前正式版本；
5. 用户确认后更新相关日期、路线和天气位置；
6. 保存新版本并展示修改摘要。

### 5.4 最终生成

1. 用户请求生成最终路书；
2. 系统执行完整性检查；
3. 有阻断问题时停止生成，并列出需要处理的内容；
4. 只有天气缺失或未验证备注时允许继续；
5. 检查通过后生成不可被草稿静默覆盖的最终版本；
6. 生成与该版本一致的 HTML 页面。

## 6. 功能需求

### 6.1 路书管理

| 编号 | 需求 |
| --- | --- |
| MVP-RB-001 | 用户可以创建一份新路书。 |
| MVP-RB-002 | 每份路书具有唯一 ID、标题、状态、创建时间和更新时间。 |
| MVP-RB-003 | 用户可以查看并继续编辑已有草稿。 |
| MVP-RB-004 | 系统自动保存每次已确认的有效修改。 |

### 6.2 对话与需求提取

| 编号 | 需求 |
| --- | --- |
| MVP-CV-001 | 系统识别出发地、开始日期、天数、交通方式、目标地点、必去项、排除项和强度偏好。 |
| MVP-CV-002 | 系统区分用户明确内容、默认值、系统推断和待确认内容。 |
| MVP-CV-003 | 缺少阻断信息时，每轮询问 1～3 个关键问题。 |
| MVP-CV-004 | 用户回答后，系统更新需求摘要并说明本轮变化。 |
| MVP-CV-005 | 对“第二天”“这个地点”等引用，系统应解析到当前路书对象；无法唯一解析时请求澄清。 |

### 6.3 地点数据

| 编号 | 需求 |
| --- | --- |
| MVP-POI-001 | 系统通过高德检索用户输入的地点并保存供应商 POI ID。 |
| MVP-POI-002 | 地点保存名称、地址、行政区、经纬度和 GCJ-02 坐标系。 |
| MVP-POI-003 | 多候选或低置信度匹配必须由用户确认。 |
| MVP-POI-004 | 无法定位的地点不得作为已验证地点进入正式路线。 |
| MVP-POI-005 | 用户可以添加自定义备注，但备注不改变地点事实。 |

### 6.4 行程与路线

| 编号 | 需求 |
| --- | --- |
| MVP-IP-001 | 系统按日期生成连续的每日行程。 |
| MVP-IP-002 | 每个行程日包含有序地点列表和相邻地点路线段。 |
| MVP-IP-003 | 路线段保存起点、终点、方式、距离、预计耗时、查询时间和验证状态。 |
| MVP-IP-004 | 系统尽量减少明显折返，并遵守必去和排除约束。 |
| MVP-IP-005 | 路线查询返回多个方案时，MVP 默认采用供应商首选方案。 |
| MVP-IP-006 | 路线失败时保留地点安排，将路线段标为未验证并提示用户。 |

### 6.5 天气

| 编号 | 需求 |
| --- | --- |
| MVP-WE-001 | 系统通过和风天气 API 查询每日主要停留地的逐日预报。 |
| MVP-WE-002 | 临近出行时，系统可以查询 24 小时逐小时预报。 |
| MVP-WE-003 | 系统查询并展示当前有效灾害预警。 |
| MVP-WE-004 | 天气保存地点、预报时间、供应商更新时间、查询时间和状态。 |
| MVP-WE-005 | 预报范围外显示“暂不可获取”，不得生成虚构天气。 |
| MVP-WE-006 | 天气失败不阻断路书；旧数据可保留，但必须标记过期。 |
| MVP-WE-007 | 恶劣天气只生成风险提示和调整建议，不自动修改正式路线。 |

### 6.6 修改、确认与版本

| 编号 | 需求 |
| --- | --- |
| MVP-ED-001 | 用户可以增加、删除或替换地点。 |
| MVP-ED-002 | 用户可以要求只重新规划指定日期。 |
| MVP-ED-003 | 不受影响的日期应保持不变。 |
| MVP-CF-001 | 删除必去地点、改变总天数、修改多个日期或改变主要跨城路线必须确认。 |
| MVP-CF-002 | 待确认修改只生成预览，不覆盖当前版本。 |
| MVP-VE-001 | 每次确认后的有效修改产生递增版本号。 |
| MVP-VE-002 | 版本记录修改时间、修改摘要和触发它的用户表达。 |
| MVP-VE-003 | 用户可以撤销最近一次有效修改；撤销本身产生新版本。 |

### 6.7 检查与最终页面

| 编号 | 需求 |
| --- | --- |
| MVP-VC-001 | 检查日期和每日行程是否连续。 |
| MVP-VC-002 | 检查所有正式地点是否具有有效坐标。 |
| MVP-VC-003 | 检查相邻地点是否存在已验证路线或明确的未验证提示。 |
| MVP-VC-004 | 检查必去地点是否遗漏、排除地点是否误入。 |
| MVP-VC-005 | 检查是否存在未处理的重要变更提案。 |
| MVP-PG-001 | 页面展示概览、每日行程、地图、路线、距离、耗时、天气、预警和提示。 |
| MVP-PG-002 | 点击行程地点时地图定位到对应标记。 |
| MVP-PG-003 | 页面明确区分正式内容、待确认预览和未验证内容。 |
| MVP-FN-001 | 最终页面必须绑定一个明确的最终版本。 |
| MVP-FN-002 | 后续修改不得覆盖已生成的最终版本。 |

## 7. 业务状态

### 7.1 路书状态

| 状态 | 含义 |
| --- | --- |
| `draft` | 基础信息不足或尚未生成行程。 |
| `planning` | 正在查询地点、路线或生成初稿。 |
| `pending_confirmation` | 存在重要修改提案。 |
| `editable` | 已有可用初稿，可继续局部修改。 |
| `blocked` | 存在无法生成最终版的阻断问题。 |
| `final` | 已生成最终版本。 |

### 7.2 外部事实状态

| 状态 | 含义 |
| --- | --- |
| `verified` | 已通过当前供应商接口成功查询。 |
| `unverified` | 尚未查询成功或属于用户备注。 |
| `stale` | 曾成功查询，但已超过有效期。 |
| `unavailable` | 当前接口未返回可用数据。 |
| `conflicted` | 多个候选或数据存在冲突，等待用户确认。 |

  },
  "places": [],
  "days_plan": [
    {
      "date": "2026-08-10",
      "place_ids": [],
      "segments": [],

## 9. 页面需求

一期使用单页面布局：

- 左侧：对话区和输入框；
- 中间：需求摘要、每日行程和修改提示；
- 右侧：地图、地点标记和分日路线；
- 顶部：标题、日期、天数、交通方式、状态和版本；
- 提示区域：天气预警、路线失败、未验证内容和待确认提案。

移动端不是一期强制验收项，但页面不得完全无法使用；可以将对话、行程和地图纵向排列。

## 10. 外部接口规则

### 10.1 高德地图

- 使用地理编码、POI 关键字检索和路径规划接口；
- 服务端保存 API Key，前端不得接触 Web 服务 Key；
- 坐标统一为 GCJ-02；
- 同一地点优先复用供应商 POI ID；
- 同一路线参数允许缓存，路线结果保存查询时间；
- 同时检查 HTTP 状态与高德 `status/infocode`。

### 10.2 和风天气

- 使用项目专属 API Host；
- 使用 `X-QW-Api-Key` Header 认证；
- HTTP 客户端必须支持响应自动解压；
- 使用三日预报、24 小时预报和灾害预警接口；
- 预警数组为空属于正常结果；
- 同时检查 HTTP 状态与和风 `code`；
- 天气按日期和主要停留地点缓存。

### 10.3 凭证安全

- API Key 只从服务端环境变量读取；
- 仓库只提供 `.env.example` 占位符；
- 日志不得输出 Key、认证头或带 Key 的完整 URL；
- 分享页面不得包含供应商凭证或原始接口响应。

## 11. 失败与降级

| 场景 | 系统行为 |
| --- | --- |
| 地点无结果 | 提示用户修改名称或提供行政区，不创建虚假地点。 |
| 地点多候选 | 展示候选并等待确认。 |
| 路线无结果 | 保留地点，路线标为未验证，不生成虚假距离。 |
| 高德超时或限流 | 有缓存时使用缓存并标记查询时间；无缓存时明确失败。 |
| 天气无结果 | 显示“天气暂未获取”，路线继续生成。 |
| 天气超出预报范围 | 显示“尚未进入可预报范围”。 |
| 天气数据过期 | 可以展示，但必须标记过期并允许重新查询。 |
| 预警存在 | 显著提示，但不自动修改已确认行程。 |
| 页面生成失败 | 保留当前有效路书，允许重试。 |
| 局部修改失败 | 保留修改前版本，不影响其他日期。 |

## 12. 非功能需求

### 12.1 一致性

- 对话摘要、行程、地图和最终页面必须绑定同一版本；
- 距离、耗时和地点坐标不得在不同区域无说明地不一致。

### 12.2 可靠性

- 每次确认修改先生成新版本，再切换当前版本；
- 外部查询失败不得删除已有有效数据；
- API 调用设置超时、有限重试和明确错误状态。

### 12.3 性能体验

- 用户消息提交后立即显示已接收状态；
- 外部查询显示地点解析、路线生成和天气查询阶段；
- 可并行的地点、路线和天气查询应并行执行；
- 局部修改只刷新受影响的行程和地图内容。

### 12.4 隐私与安全

- 分享页面默认不展示精确家庭住址等敏感地点；
- API Key 不进入浏览器、数据库业务对象和分享内容；
- 用户备注仅用于当前路书，不作为长期偏好保存。

## 13. 固定提示

草稿与最终页面均展示：

> 本路书依据地点、地图路线及和风天气预报生成。天气预报可能变化；景点开放、预约、票价、交通班次、住宿库存及临时管制未自动核实，请在出发前通过官方渠道确认。

## 14. 一期验收标准

### 14.1 主流程

1. 用户输入一个中国境内三日自驾需求，包含出发地和 3～5 个地点；
2. 系统识别日期、天数、方式和地点，并对缺失信息进行不超过三项的补问；
3. 系统对重名地点展示候选并由用户确认；
4. 系统生成连续三天的结构化行程；
5. 地图正确展示地点标记和分日路线；
6. 页面展示每日路线距离、预计耗时和主要地点天气；
7. 若存在天气预警，页面展示预警标题和有效时间；
8. 用户要求替换第二天一个地点；
9. 系统展示影响并在确认后只更新第二天、关联路线和天气位置；
10. 修改后产生新版本，并能撤销最近一次修改；
11. 最终检查通过后生成绑定最终版本的 HTML 页面。

### 14.2 降级流程

- 模拟高德地点无结果时，系统不生成虚假坐标；
- 模拟路线失败时，地点行程仍然保留；
- 模拟和风天气失败时，路线和最终页面仍可生成；
- 模拟天气过期时，页面明确显示过期状态；
- 模拟局部修改失败时，修改前版本仍可正常访问；
- 所有页面和日志均不出现 API Key。

## 15. 开发前置项

1. 确定服务端技术栈、数据库和前端地图技术方案；
2. 将高德和和风凭证配置到本地服务端环境变量；
3. 建立 `.env.example`，禁止提交真实凭证；
4. 定义 RouteBook、Place、RouteSegment、Weather、Proposal 和 Version 的技术模型；
5. 先实现高德和和风适配器及统一错误类型；
6. 用本文第 14 节场景建立端到端验收用例。
