# 路书 Agent 文档中心

本文档目录按“需求基线、设计规范、开发文章、调研记录”组织。

## 1. 阅读顺序

1. 开发一期功能：先读[一期功能需求](requirements/01-路书Agent一期功能需求.md)，再读[第三方接口接入规范](design/01-第三方接口接入规范.md)、[一期技术方案](design/02-一期技术方案.md)和[一期开发计划](design/03-一期开发计划.md)。
2. 了解完整产品规划：读[整体产品需求](requirements/00-路书Agent整体产品需求.md)。
3. 追溯范围和技术选型原因：查看 `research/` 下的调研与验证记录。
4. 阅读从 0 到 1 的开发过程：查看[第一篇开发记录](articles/01-从一个旅行计划到路书Agent.md)和[第二篇开发记录](articles/02-用LangGraph和高德POI跑通路书Agent最小闭环.md)。

## 3. 文档定位

| 文档 | 定位 | 是否作为一期开发基线 |
| --- | --- | --- |
| 整体产品需求 | 描述完整产品愿景、长期功能和业务规则 | 否 |
| 一期功能需求 | 明确一期范围、流程、功能和验收标准 | 是 |
| 第三方接口接入规范 | 规定高德与和风天气的服务端接入方式 | 是 |
| 一期技术方案 | 规定一期技术选型、LangGraph 编排、数据版本和实施方案 | 技术设计基线 |
| 一期开发计划 | 定义 0～8 阶段任务、退出标准和实施顺序 | 开发执行基线 |
| 第二阶段 POI 对抗评测 | 覆盖景区主体、附属设施、交通与同名商户误采用风险 | 阶段 2 回归基线 |
| 第二阶段退出审计 | 逐项关联阶段任务、退出标准、代码、测试和待验证证据 | 阶段 2 门禁记录 |
| 第三阶段需求评测 | 覆盖完整、缺失、非法、歧义和模型推荐污染场景 | 阶段 3 回归基线 |
| 第三阶段退出审计 | 关联需求对话实现、恢复链路、评测和外部待验证证据 | 阶段 3 门禁记录 |
| 从一个旅行计划到路书 Agent | 记录一期需求发掘、范围裁剪和技术方案形成过程 | 否 |
| 用 LangGraph 和高德 POI 跑通路书 Agent 最小闭环 | 记录首个可运行原型、真实接口调试和阶段性体会 | 否 |
| 一期范围裁剪记录 | 记录为何保留或删除某些能力 | 否 |
| 外部数据源调研 | 记录候选数据源、限制和后续方向 | 否 |
| 第三方接口验证记录 | 记录真实接口验证结果 | 验证依据 |

## 4. 文档优先级

发生冲突时按以下顺序处理：

1. 一期功能需求；
2. 第三方接口接入规范；
3. 一期技术方案；
4. 整体产品需求；
5. 调研和验证记录。

整体产品需求描述“最终要具备什么能力”，不代表一期必须实现。调研文档用于解释决策，不直接新增开发范围。

## 5. 命名规则

- `00-`：整体或总览文档；
- `01-`：当前一期或该目录第一份实施文档；
- `requirements/`：产品必须实现和验收的内容；
- `design/`：开发必须遵循的技术与接口约定；
- `articles/`：面向社区发布的项目开发过程记录；
- `research/`：调研、验证和历史决策记录。
